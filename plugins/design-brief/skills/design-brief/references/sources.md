# Where this design comes from

Written fresh for this repo. No text was copied from the sources below, which are widely used
design and product practices.

- **Jobs to be done.** Describe what a person is trying to get done, not the feature that might
  help them
- **User-centred design.** Know who uses it and in what conditions, and test with real people.
  Reflected in ISO 9241-210 and in public service design standards
- **Acceptance criteria.** A finish line that can be checked, used across agile teams
- **Accessibility guidance.** The Web Content Accessibility Guidelines, including contrast,
  labels and keyboard use

## Design choices

- **Guess first, then ask,** so the user can answer in one word and the brief costs minutes
- **Five questions at most,** because a long interview reads as stalling
- **"Won't" is required,** because scope creep is the commonest way a good brief fails mid-build
- **Skip it when the ask is small or already clear,** so the skill never costs more than it saves
